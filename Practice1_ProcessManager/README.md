# Practice1_ProcessManager

Консольное приложение .NET 9: запускает разрешённую утилиту `dotnet --info`, выводит PID, длительность выполнения и код завершения. Ошибка запуска обрабатывается и не приводит к аварийному завершению.

## Запуск

```powershell
dotnet run --project Practice1_ProcessManager.csproj
```

Ожидаемый результат:

```text
PID: 12345
Длительность: 00:00:01.2345678
Exit code: 0
```

## Проверки

1. **Успешный запуск.** `dotnet --info` завершается с кодом `0`.
2. **Ошибочный запуск.** Временно замените `FileName = "dotnet"` на `FileName = "missing-tool-12345.exe"` и запустите снова. Приложение должно вывести сообщение `Ошибка запуска: ...`, а не упасть с необработанным исключением. В этом случае `Environment.ExitCode` равен `1`.

## Почему нужен `WaitForExitAsync()`

`Process.ExitCode` имеет смысл только после завершения процесса. Если убрать ожидание:

- процесс может ещё работать, и код завершения ещё не сформирован;
- если процесс не завершился, обращение к `ExitCode` бросает `InvalidOperationException` («process has not exited»);
- если процесс успел завершиться сам, значение может оказаться доступным — но это гонка, на которую нельзя рассчитывать;
- `Win32Exception` этот случай не перехватывает, поэтому приложение завершится аварийно.

`await process.WaitForExitAsync()` гарантирует, что процесс завершился, и только после этого код читает `ExitCode`.
